---
name: Development checkpoint checklist
description: How project progress must be reported and persisted after every completed development unit.
---

After every development unit, update the canonical build checklist so the user can always see the exact lifecycle stage, maturity level, evidence, remaining risks and single next checkpoint.

**Why:** The user explicitly requested a continuously updated checklist rather than relying on conversational summaries that become ambiguous across long implementation waves.

**How to apply:** Mark progress only after verification. Keep implementation status, proof, risks and next checkpoint synchronized with the Capability Index and workflow map. Never promote an item from interface presence or historical claims alone.
