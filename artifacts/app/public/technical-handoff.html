Section 00

Project Overview & Current State

NexOS AI is a full-stack AI-powered growth execution platform built as a pnpm monorepo. The platform transforms business intention into complete commercial campaign execution — from strategy to launch to monitoring — using 64 specialized AI agents.

Current Status: The platform is functionally complete at the MVP level. Backend API, frontend app, database schema, AI pipeline, and all core modules are built and typechecking cleanly. The main remaining work is production hardening, testing coverage, and a few roadmap features (HeyGen avatar, domain hosting, etc.).

Section 02

Environment Setup & Local Development

Prerequisites

  • Node.js 24+ — required (the project targets Node 24 features)
  • pnpm 10+ — package manager (npm install -g pnpm)
  • PostgreSQL 15+ — local database or hosted (Supabase, Neon, etc.)
  • Redis — optional for local dev (BullMQ + Socket.io degrade gracefully without it)

Initial Setup

# 1. Clone and install
git clone <repo-url> nexos-ai
cd nexos-ai
pnpm install

# 2. Set environment variables (see Section 03)
cp .env.example .env   # if exists, or set manually

# 3. Push database schema
pnpm --filter @workspace/db run push

# 4. Seed plans (REQUIRED before first user registration)
cd lib/db && npx tsx src/seed-plans.ts

# 5. Start services (each in a separate terminal)
pnpm --filter @workspace/api-server run dev   # API on port 8080
pnpm --filter @workspace/app run dev          # Frontend on $PORT
pnpm --filter @workspace/landing run dev      # Landing page
pnpm --filter @workspace/nexos-academy run dev # Academy

Important: Run Order for Type Checking

When DB schema changes, ALWAYS run in this order:
1. pnpm run typecheck:libs — builds lib/db declarations
2. pnpm --filter @workspace/api-server run typecheck
3. pnpm run typecheck — full workspace check

# Full typecheck (recommended before any PR)
pnpm run typecheck:libs && pnpm run typecheck

# DB schema change workflow
pnpm --filter @workspace/db run push    # dev only, applies migration
pnpm run typecheck:libs                  # rebuild lib declarations
pnpm run typecheck                       # verify everything compiles

Model name gotcha: GPT-5.x models require max_completion_tokens NOT max_tokens. The callOpenAI() function auto-detects gpt-5.* model names and switches the parameter automatically. Do NOT change this behavior without testing both model families.

Agent Runner Architecture

File: artifacts/api-server/src/modules/agents/agent.runner.ts

Every agent call goes through runAgent(opts) which:

  1. Injects DOMINO CORE persuasion framework (mandatory for all agents)
  2. Injects Cognitive Foundations layer (16 thinkers, 5 pillars)
  3. Injects Constraint Reasoning layer
  4. Injects NEXOS_MASTER_EVOLUTION_PROMPT
  5. Calls the provider-specific completion function
  6. Logs to aiProviderLogs + campaignAgents tables
  7. Deducts credits from workspace balance
  8. Returns AICompletionResult with .content string

// 5. Create your agent file
// artifacts/api-server/src/modules/agents/my-new.agent.ts
export async function runMyNewAgent(campaignId, workspaceId, data, log) {
  const result = await runAgent({
    agentRole: "my_new_agent",
    messages: [{ role: "user", content: buildPrompt(data) }],
    workspaceId,
    campaignId,   // pass null for sequence-level agents
    log,
    creditAction: "my_action",
  });
  return parseAgentJSON(result.content);
}
Section 06

Campaign Execution Pipeline

State Machine

File: artifacts/api-server/src/modules/campaigns/campaign-state-machine.ts

The state machine is the single source of truth for campaign status transitions. Never call db.update(campaigns).set({ status }) directly — always use transitionCampaign().

// Valid transition flow
intake → analyzing → strategy_ready → generating
→ awaiting_approval → approved → executing → live → completed

// Error states
any → failed
executing → paused → executing  // via retry

Execution Entry Points

EndpointPhase triggeredWhat happens
POST /campaigns/:id/execute/strategyStrategyRuns intake → command → profile → strategy agents
POST /campaigns/:id/execute/contentContentRuns all 16 content agents with checkpoint/resume
POST /campaigns/:id/execute/launchLaunchIntegration gate check → activates sequences → goes live
POST /campaigns/:id/execute/monitorMonitorAnalytics + optimization agents
POST /campaigns/:id/execute/retryRecoveryClears pipeline lock + force-resets status + re-enqueues

BullMQ + Fallback

When Redis is unavailable: enqueueOrExecute() in orchestration.service.ts detects the Redis connection failure and falls back to setImmediate() direct execution. The HTTP response always returns 202 immediately. Never block the HTTP thread for AI execution.

Content Generation Checkpoint / Resume

File: artifacts/api-server/src/modules/agents/command.agent.ts

Each of the 16 content agents is wrapped with skipAgent(campaignId, agentType). On each call, it checks if the content piece already exists in the DB — if yes, skips and uses existing. On server restart, resumeGeneratingCampaigns() is called at boot to re-enqueue any campaigns stuck in generating state.

Section 11

Deployment Guide

Architecture Overview

The platform runs as a reverse-proxied multi-service monorepo. A global proxy routes traffic by path prefix to individual services:

PathServicePort
/api/*api-server (Express)8080
/app (React/Vite)$PORT
/landinglanding (React/Vite)$PORT
/nexos-academynexos-academy (React/Vite)$PORT

Port binding: All Vite-based frontends MUST read process.env.PORT for their dev server port. Hard-coded ports (e.g., server: { port: 3000 } in vite.config.ts) will cause blank preview panes on Replit because the proxy assigns a unique port per service.

Build Commands

# Build API server (esbuild CJS bundle)
pnpm --filter @workspace/api-server run build

# Build all frontends
pnpm --filter @workspace/app run build
pnpm --filter @workspace/landing run build
pnpm --filter @workspace/nexos-academy run build

# Full build (typecheck + build all)
pnpm run build

Production Checklist

  • ☐ DATABASE_URL set to production PostgreSQL
  • ☐ SESSION_SECRET = random 64-char string (never the same as dev)
  • ☐ JWT_SECRET = separate random string
  • ☐ REDIS_URL set (without Redis, no real-time events in production)
  • ☐ ANTHROPIC_API_KEY + OPENAI_API_KEY + GEMINI_API_KEY set
  • ☐ ALLOWED_ORIGINS = your production domain(s)
  • ☐ APP_URL = your production URL
  • ☐ Database schema pushed: pnpm --filter @workspace/db run push
  • ☐ Plans seeded: npx tsx lib/db/src/seed-plans.ts
  • ☐ Admin emails updated in code (see Section 03)
  • ☐ Payment webhook URLs configured in Hotmart/Kiwify/Stripe dashboards
  • ☐ Meta webhook URL configured: POST /api/whatsapp/webhook
