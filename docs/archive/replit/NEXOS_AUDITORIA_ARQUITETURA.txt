  PARTE 2 — BUGS CONHECIDOS COM STATUS ATUAL
  ================================================================================

  BUG #01 — agentRole "copywriter" hardcoded em 11 agentes
    Severidade: CRÍTICO
    Status: CORRIGIDO (Jul 2026, commit 1f88948)
    Impacto se não tivesse corrigido: VSL, Anúncios, Social, WhatsApp entregam
    JSON no formato errado — entregáveis completamente inutilizáveis.

  BUG #02 — content_calendar entrega calendar:[] (zero dias)
    Severidade: CRÍTICO
    Status: ABERTO
    Causa: LLM trunca antes de completar 20+ posts. Anthropic sem créditos →
           fallback OpenAI → resposta incompleta → parseAgentJSON retorna default vazio.
    Impacto: Lançador aprova calendário vazio sem saber; equipe de social sem plano.
    Solução necessária: Chunked generation (separar em blocos de 7 dias como targeting agent).

  BUG #03 — Contract violations não bloqueiam peça nem disparam retry
    Severidade: CRÍTICO
    Status: ABERTO (follow-up tasks #22–#24 em andamento)
    Causa: _contractViolation:true é setado mas peça avança para pending_approval.
    Impacto: Entregáveis fora do contrato são aprovados e usados em campanha real.

  BUG #04 — Social auto-post dispara imediatamente após aprovação
    Severidade: CRÍTICO
    Status: ABERTO
    Causa: autoPostApprovedContent() é fire-and-forget sem gate de confirmação.
    Impacto: Usuário aprova peça internamente para revisão e post vai ao ar sem querer.

  BUG #05 — Dupla execução no scheduler
    Severidade: IMPORTANTE
    Status: ABERTO (documentado em NEXOS_WORKFLOW_MAP.md)
    Causa: Quando Redis volta online, BullMQ Job + setInterval Fallback disparam juntos.
    Impacto: Mesmo email/WhatsApp enviado duas vezes para a lista — dano de reputação.

  BUG #06 — Credenciais salvas sem validação prévia
    Severidade: IMPORTANTE
    Status: ABERTO
    Causa: Token inválido é salvo com status:"connected" sem ping de teste.
    Impacto: Lançamento inicia, chega na hora de publicar, falha silenciosamente.

  BUG #07 — Idempotência de créditos em reinício de pipeline
    Severidade: IMPORTANTE
    Status: PARCIAL
    Causa: skipAgent() protege agentes com output salvo, mas depende de pieceStatus
           estar correto antes do restart.
    Impacto: Créditos deduzidos duas vezes pelo mesmo trabalho em caso de restart.

  BUG #08 — Graceful degradation tratada como sucesso
    Severidade: IMPORTANTE
    Status: ABERTO
    Causa: Resend sem API key loga "skip" sem alertar o usuário. Email nunca chega.
    Impacto: Sequência roda, dispatch aparece como ok, zero emails entregues.

  BUG #09 — autoGenerateCreativesFromBrief() dispara sem gate
    Severidade: MENOR
    Status: ABERTO (previsto para Fase 3 no NEXOS_WORKFLOW_MAP.md)
    Impacto: Créditos DALL-E consumidos sem confirmação do usuário.

  BUG #10 — Validação sem evidência externa
    Severidade: IMPORTANTE
    Status: ABERTO
    Obs: Critério de 3 execuções limpas consecutivas não atingido. Verificação
         baseada apenas em logs internos — sem confirmação de email recebido,
         post publicado no Instagram, etc.

  ------------------------------------------------------------------------

  Onde se encaixa:
    Entre etapa #4 (Intake completo) e etapa #6 (command.agent inicia).

    Opção B: como fase interna de "analyzing" antes do command.agent

  O que já existe de base:

    - conflict-detector.service.ts — detecta contradições, persiste em brainData

    - Campo em brainData para persistir resultados (aprovado/ajustar/rejeitado)

    - UI de review dos resultados (similar aos checkpoints de estratégia)
    - Integração no fluxo de execução

  Risco de conflito: ALTO
    Inserir antes de /execute {phase:"strategy"} requer nova transição de estado.
    Inserir dentro de "analyzing" compete com command.agent que já inicia imediatamente.
    Abordagem mais segura: rodar os 3 antes de invocar command.agent dentro de "analyzing".

  ADAPTAÇÃO 5 — NEXOS BRIDGE (navegação assistida)
  ------------------------------------------------------------------------

  Base existente: NENHUMA

  RISCOS CRÍTICOS DE ARQUITETURA:

  Risco 1 — Fronteira tecnológica não-garantível por software
    A promessa "nunca insere senha/credencial" é intenção, não propriedade técnica
    verificável. Um webview que abre URLs externas não pode distinguir programaticamente
    campo de senha de campo de texto livre. A fronteira só é segura se o Bridge
    APENAS abre o browser nativo do usuário (tab externa) e nunca embute o site
    externo em iframe controlado pelo NexOS.

  Risco 2 — Termos de Serviço das plataformas
    Meta, TikTok e Google proíbem explicitamente automação de navegação em suas
    consoles de desenvolvedor. Guiar cliques em páginas externas é grey area que
    pode resultar em suspensão do app OAuth registrado.

  Risco 3 — Phishing aparente
    Componente que abre telas de redes sociais dentro do produto e instrui onde
    clicar é indistinguível de ataque de phishing para usuários menos técnicos —
    risco de rejeição em revisões de app store em versão mobile futura.

  Implementação tecnicamente segura:
    Deep-link para URL exata (abre browser nativo do usuário) + screenshot/GIF
    anotado mostrando onde clicar + checklist de confirmação manual no produto.
    Qualquer webview controlado pelo NexOS cria risco de ultrapassar a fronteira.
