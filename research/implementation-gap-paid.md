Findings (read-only):

FOUNDATION / REAL PROVIDER MUTATIONS
- Paid-media control plane is `artifacts/api-server/src/modules/paid-media/` with DB schema `lib/db/src/schema/paid-media.ts`. Accounts/entities/insights/sync cursors/proposals/approvals/action attempts already exist (schema lines 70-213, 247-334). Providers are only `meta_ads` and `tiktok_ads` (`paid-media.ts:21-25`, `providers.ts:19`); Google Ads is not an executable provider.
- Real sync exists: `sync.service.ts` calls adapter account/entity/insight APIs and persists normalized data; worker is `paid-media.worker.ts`. Real mutations are gated proposal→approval→execute and verified/rollback in `actions.service.ts:22-89`; execution calls `adapter.applyAction` (`:55-66`), not mocks.
- Meta adapter uses live Graph API v20 (`providers.ts:160-239`): lists ad accounts/entities and insights; actual POST mutation supports only pause/resume/daily budget/bid (`:218-230`), explicitly rejects creative status/rotation (`:227`). TikTok uses live Business API (`:242-305`), lists campaign/adgroup/ad, fetches reports, mutates pause/resume/budget/bid, and explicitly cannot list creatives (`:270-273`). Thus creative pausing is not implemented despite enum/action type support.
- Existing action enum includes `cross_platform_budget_move` and schema stores before/after allocation (`paid-media.ts:51-59, 261-266`), but policy explicitly makes cross-platform movement non-auto (`actions.service.ts:10-19`) and routes only generate actions `pause|resume|update_daily_budget|update_bid` (`paid-media.routes.ts:169-175`). No source/destination transfer executor exists. Current budget updates are entity-local only.

MISSING PROVIDER OPERATIONS
- No pixel module/routes/schema/service found for installation, browser/server events, conversion events, pixel-derived audiences, health/diagnostics, deduplication, event match quality, or test events. `integration-wizard.routes.ts:60` only gives setup instructions mentioning Meta Web Events; it does not install/emit/diagnose.
- No audience creation/mutation adapter or audience schema/routes. Regional intelligence has planning/storage/scoring (`regional-audience-scoring.ts`, market-intel services), but no provider activation. Existing `paidMediaEntityKind` is campaign/ad_set/ad/creative only (`providers.ts:19-20`; schema `paid-media.ts:27-32`).
- No campaign/ad-set/ad/creative creation APIs: adapters only `listEntities`, `fetchInsights`, snapshots and action patch. `paid-media.routes.ts` exposes discovery, sync, proposals, approvals/execution, policies—not creation routes. TikTok creative listing is explicitly unsupported. Google configuration env vars exist (`lib/env.ts:30-31`) but no Google paid-media adapter/provider/routes/service.
- No CBO/ABO model or mutation/decision service. Campaign entity data is synced but there are no budget-level semantics, ad-set budget allocation, campaign `campaign_budget_optimization`, or validation. Academy copy is planning/education only (`artifacts/nexos-academy/src/data/curriculum.ts:4845-4887`) and must not be treated as implementation.

METRICS / CRM / ATTRIBUTION
- Generic campaign metrics are substantially present: `metrics.service.ts:312-630` ingests/upserts daily clicks/impressions/spend/CPL/CTR/leads/sales/revenue/ROAS/conversion rate and generates fatigue/ROAS/CPL alerts (`:199-225, :270-305`). Summary calculates aggregate ROAS (`:634-694`); routes are under `metrics.routes.ts:17-137`.
- Paid-media insights schema stores impressions/clicks/spend/conversions/value and attribution window (`paid-media.ts:171-213`), but no cross-source attribution join, CRM/contact/order identity, UTM/click IDs, Meta CAPI/TikTok Events/Google conversion import, or conversion deduplication. Therefore CPA/ROAS/CTR are not consolidated by provider/entity/creative with CRM outcomes. Existing launcher/dashboard displays campaign-level ROAS/CPL (`artifacts/app/src/pages/launcher/index.tsx:355-365, 723-725`) but not a trustworthy paid-media+CRM attribution view.
- CRM foundations exist elsewhere (conversations, contacts, funnel stages, conversions/messages), but no linkage service was found connecting them to paid-media entity IDs/click IDs or allocating revenue to campaigns/ads. Extend schema with attribution touchpoints, CRM conversion events, external IDs, and reconciliation/status rather than reusing planning metrics.

UI / TEST FOUNDATIONS
- Paid-media UI is `artifacts/app/src/pages/paid-media/index.tsx:8-45`, currently only Accounts/Sync, Policies, Proposals, Attempts. Extend with provider setup/pixel diagnostics, audiences, campaign builder, CBO/ABO, creatives, reallocations, and attribution dashboards. Existing components are `pages/paid-media/components/{AccountsTab,PoliciesTab,ProposalsTab,AttemptsTab}.tsx`.
- Existing real-provider/E2E test foundations: `artifacts/api-server/src/scripts/test-paid-media.ts`, `test-meta-e2e-harness.ts`, `test-meta-app-review.ts`, `scripts/README.meta-e2e.md`; regional audience tests (`test-regional-audience-scoring.ts`, `test-regional-intelligence-db.ts`) test planning/database behavior, not provider audience activation. Do not use `e2e-fixtures.ts` as proof of real mutation—it creates fixture/proposal records.

DEPENDENCY ORDER
1) Provider credentials/scopes and canonical account ownership; add Google adapter only after OAuth/token model and provider enum support. Preserve real API transport/error/idempotency conventions in `providers.ts`.
2) Schema primitives: pixels/datasets + event receipts/deduplication/diagnostics; audiences and provider audience IDs; campaign/adset/ad/creative creation records; budget strategy CBO/ABO; CRM attribution touchpoints/conversions and currency/timezone-aware metric facts.
3) Implement Meta first (pixel/CAPI/events/audiences/create hierarchy/creative upload+pause/CBO-ABO), then TikTok equivalents, then Google campaign/ad-group/ad/remarketing/conversion operations. Add adapter interfaces and routes with approval/audit/verification—not direct UI calls.
4) Build creation orchestration (campaign→ad set/ad→creative), audience activation, diagnostics, and creative pause as real provider mutations; wire proposal/action types and route validation. Then implement cross-campaign reallocations as atomic, multi-entity proposals requiring human approval, with source/destination snapshots and verification.
5) Add CRM attribution ingestion/reconciliation and calculate consolidated CPA (spend/conversions), ROAS (CRM revenue/spend), CTR (clicks/impressions), with explicit attribution windows and unknown/unattributed buckets. Extend metrics service/routes only after canonical facts exist.
6) Extend paid-media UI and generated API client/types; finally add contract tests (adapter request payloads), provider sandbox/E2E tests with opt-in real credentials, verification/rollback/idempotency tests, attribution reconciliation tests, and UI tests. Current generic metrics and academy content must remain planning/analytics foundations, not claims of provider execution.
