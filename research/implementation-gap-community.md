**Ausências exatas a implementar**
1. Inbox ingestion cross-channel: contrato/event envelope comum; tabelas workspace-scoped para accounts/conversations/participants/messages/attachments/provider event IDs/status; webhook + backfill/polling por Meta IG/FB messaging, WhatsApp, Telegram (e eventual TikTok onde API permitir); dedupe/ordering/threading, routing por integração e UI de inbox. Hoje `processMetaWebhook` é acoplado ao callback social e WhatsApp só processa `text` inbound, não persiste mensagem geral (`whatsapp.service.ts:419-480`).
2. WhatsApp/Telegram group creation: provider adapters, capability checks, credential/account selection, real provider IDs/links and audit/evidence. Extend groups schema/service/routes with provider lifecycle/status/error/last sync, not just `memberCount`. Official capability boundary: WhatsApp Business Cloud API does not provide a general official API for creating arbitrary groups or enumerating/inviting/removing group participants; do not promise those mutations (would require unsupported/WhatsApp-user automation). Telegram Bot API bots cannot create a group; an admin can add/promote/restrict/ban users and receive group updates, but member discovery is permission/visibility-limited. Product must expose “connect existing group / bot admin” and unsupported states rather than fake success.
3. Member ingestion: Telegram `getChatMember(s)`/updates where permitted, WhatsApp no equivalent general group member ingestion; persist participant/member snapshots, consent/identity provenance, sync cursors and failures. `memberCount` is currently caller-supplied (`groups.routes.ts:21-23`) and not evidence of ingestion.
4. Community moderation: generalized rule schema (keyword/regex/classification/rate/link/role), policy evaluation, queue/approval, provider adapter capabilities, actions/audit/idempotency. Extend existing comment AI classification rather than conflate it; add message/group/member moderation records and real Telegram restrict/ban/delete operations where authorized. WhatsApp group moderation mutations must be capability-gated as unsupported; Meta comment actions remain separate.
5. Autonomous responses: durable inbound event → policy → AI/deterministic response → safety/approval → provider send → delivery/retry/audit, channel-specific templates/24h WhatsApp window/template requirements and Telegram bot permissions. `whatsapp-response.agent.ts` is generation/execution foundation, but current webhook launches it detached and lacks unified durable conversation state. Avoid declaring “all networks auto-reply.”
